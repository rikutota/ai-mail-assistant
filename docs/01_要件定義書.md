# 要件定義書

## 1. システム概要

本システムは、GmailおよびOutlookに届いたメールを自動取得し、AIによって要約・分類・重要度判定を行い、LINEへ通知するAIメールアシスタントである。

また、予定や依頼に関するメールについては、本文から日時・場所・タイトルを抽出し、Google Calendarへ自動登録する。

処理結果はSupabaseへ保存し、後から処理履歴を確認できるようにする。

---

## 2. 目的

### 2.1 解決したい課題

- GmailとOutlookを個別に確認する手間がある
- 重要なメールを見落とす可能性がある
- 予定や依頼を手作業でカレンダー登録している
- メール本文を読むだけで時間がかかる
- 処理済みメールの履歴を後から確認しにくい

### 2.2 本システムで実現すること

- GmailとOutlookのメールを一元取得する
- メール内容をAIで短く要約する
- 重要度を High / Medium / Low で分類する
- 予定メールを検出する
- Google Calendarへ予定を登録する
- LINEへ毎朝メール要約を通知する
- Supabaseへ処理ログを保存する

---

## 3. 想定ユーザー

### 3.1 メインユーザー

- 個人利用者
- 学生
- 就職活動中のユーザー
- 副業・業務メールを複数管理しているユーザー

### 3.2 利用シーン

- 朝にその日の重要メールをまとめて確認する
- GmailとOutlookをまとめて確認する
- 予定や依頼メールを自動でカレンダー登録する
- メール処理の抜け漏れを減らす

## 5. 機能要件

### 5.1 Gmailメール取得

Gmail APIまたはn8nのGmailノードを使用し、指定条件に一致するメールを取得する。

対象メールは以下とする。

- 未読メール
- 直近24時間以内のメール
- Inbox配下のメール

取得項目は以下とする。

- メールID
- 件名
- 差出人
- 受信日時
- 本文
- スレッドID
- メールサービス種別

初期MVPでは、添付ファイルの取得は対象外とする。

---

### 5.2 Outlookメール取得

Microsoft Graph APIまたはn8nのMicrosoft Outlookノードを使用し、Outlookの受信メールを取得する。

対象メールは以下とする。

- 受信トレイ内のメール
- 未読メール
- 直近24時間以内のメール

取得項目は以下とする。

- メールID
- 件名
- 差出人
- 受信日時
- 本文
- Webリンク
- メールサービス種別

---

### 5.3 メール情報の正規化

GmailとOutlookでは取得できるデータ形式が異なるため、後続処理では以下の共通形式に変換する。

    {
      "source": "gmail",
      "messageId": "string",
      "threadId": "string",
      "sender": "string",
      "subject": "string",
      "body": "string",
      "receivedAt": "2026-07-11T08:00:00+09:00"
    }

`source` には以下のいずれかを設定する。

- gmail
- outlook

---

### 5.4 AI要約・分類

OpenAI APIを使用し、メール本文を要約・分類する。

入力情報は以下とする。

- 件名
- 差出人
- 本文
- 受信日時

AIの出力形式は以下とする。

    {
      "summary": "メール内容の要約",
      "priority": "High",
      "category": "schedule",
      "requiresAction": true,
      "isSchedule": true,
      "event": {
        "title": "打ち合わせ",
        "startDateTime": "2026-07-12T10:00:00+09:00",
        "endDateTime": "2026-07-12T11:00:00+09:00",
        "location": "オンライン",
        "description": "メール本文から抽出した予定内容"
      }
    }

重要度は以下の3段階とする。

| 値 | 意味 |
|---|---|
| High | 重要・緊急 |
| Medium | 通常確認が必要 |
| Low | 広告・通知・重要度が低い |

カテゴリは以下とする。

| 値 | 意味 |
|---|---|
| schedule | 予定・打ち合わせ |
| task | 作業依頼 |
| notice | 通知 |
| invoice | 請求・支払い |
| promotion | 広告 |
| other | その他 |

---

### 5.5 Google Calendar登録

以下の条件をすべて満たす場合のみ、Google Calendarへ予定を登録する。

- `isSchedule` が true
- 開始日時が取得できている
- 予定タイトルが取得できている
- 同一メールIDで未登録である

登録項目は以下とする。

- タイトル
- 開始日時
- 終了日時
- 場所
- 説明
- 元メール情報

終了日時が本文から取得できない場合は、開始日時から1時間後を仮の終了日時とする。

---

### 5.6 LINE通知

初期MVPでは、毎朝8時にLINE通知を送信する。

通知内容は以下とする。

- 処理対象メール数
- 重要メール一覧
- 通常メール一覧
- 予定登録結果
- エラーがあった場合の簡易情報

通知例：

    今日のメール要約

    【重要】
    1. A社：見積依頼
       7/15までに見積提出が必要です。

    【通常】
    1. 大学：イベント案内
       来週の説明会に関する案内です。

    【予定登録】
    ・7/12 10:00 A社打ち合わせ

    処理件数：8件
    予定登録：1件

---

### 5.7 Supabase保存

処理結果はSupabaseへ保存する。

保存する情報は以下とする。

- メールID
- メールサービス種別
- 件名
- 差出人
- 受信日時
- 要約
- 重要度
- カテゴリ
- 予定判定結果
- カレンダー登録結果
- 処理日時
- エラー内容

## 6. 非機能要件

### 6.1 セキュリティ

- APIキーは `.env` またはn8n Credentialsで管理する
- GitHubに秘密情報をコミットしない
- `.env.example` にはキー名のみ記載する
- SupabaseのService Role Keyはサーバー側処理でのみ使用する
- OAuthトークンは安全に管理する

### 6.2 可用性

- 1日1回の定期実行を基本とする
- APIエラー時はリトライする
- 一部サービスが失敗しても、他サービスの処理は可能な範囲で継続する
- 完全停止時はログで検知できるようにする

### 6.3 保守性

- GmailとOutlookの取得処理は共通形式に変換する
- AIプロンプトはドキュメント化する
- n8nワークフローはエクスポートしてGit管理する
- 仕様変更時はdocsを更新する

### 6.4 拡張性

将来的に以下を追加できる設計にする。

- Slack通知
- Teams通知
- 添付ファイル解析
- Webダッシュボード
- メール返信文生成
- 複数ユーザー対応

## 8. エラー時の挙動

| エラー | 対応 |
|---|---|
| Gmail取得失敗 | エラーログ保存、Outlook処理は継続 |
| Outlook取得失敗 | エラーログ保存、Gmail処理は継続 |
| OpenAI API失敗 | 対象メールを未処理として保存 |
| Calendar登録失敗 | LINE通知に失敗情報を含める |
| LINE通知失敗 | Supabaseへエラーログ保存 |
| Supabase保存失敗 | n8nの実行ログに記録 |

---

## 9. 制約事項

- Outlook連携にはMicrosoftアカウントおよびGraph API設定が必要
- Gmail連携にはGoogle Cloud設定が必要
- LINE通知にはLINE Messaging APIの設定が必要
- OpenAI API利用料が発生する
- n8nの実行環境が必要
