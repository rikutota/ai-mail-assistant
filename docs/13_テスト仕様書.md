# テスト仕様書

## 1. 概要

本ドキュメントでは、AIメールアシスタントのMVPにおけるテスト方針、テスト観点、テストケース、合格基準を定義する。

本システムは、Gmail、Outlook、OpenAI、Google Calendar、LINE、Supabase、n8nを連携するため、単体機能だけでなく、外部サービス連携とワークフロー全体の動作確認を重視する。

---

## 2. テスト目的

本テストの目的は以下である。

- Gmail / Outlookから対象メールを取得できることを確認する
- メール情報を共通形式へ正規化できることを確認する
- OpenAIで要約・分類・予定抽出できることを確認する
- Google Calendarへ予定登録できることを確認する
- LINEへ通知できることを確認する
- Supabaseへ処理ログを保存できることを確認する
- 同じメールを重複処理しないことを確認する
- 外部APIエラー時に適切にログ保存・通知できることを確認する

---

## 5. テストデータ方針

## 5.1 使用するメールデータ

テストでは、以下のようなメールを用意する。

| 種別 | 内容 |
|---|---|
| 予定メール | 面接、打ち合わせ、説明会など日時が明確なメール |
| タスクメール | 提出依頼、返信依頼、確認依頼 |
| 請求メール | 支払い、請求書、領収書 |
| 通知メール | サービス通知、大学・企業からの案内 |
| 広告メール | セール、キャンペーン、メルマガ |
| 曖昧な予定メール | 日程調整中、候補日未確定 |
| 本文なしメール | 件名のみ、本文取得失敗相当 |
| 長文メール | AI入力制限確認用 |

---

## 5.2 テストデータ利用時の注意

- 実在する個人情報を含むメールは使用しない
- APIキーやトークンを本文に含めない
- テスト用の件名・本文を用意する
- READMEやIssueに実メール本文を貼らない
- スクリーンショットに個人情報が含まれないようにする

---

## 6. テスト分類

| 分類 | 内容 |
|---|---|
| 単体テスト | 各ノード・各処理単位の確認 |
| 結合テスト | 外部APIとの接続確認 |
| E2Eテスト | メール取得からLINE通知・DB保存までの全体確認 |
| 異常系テスト | API失敗、認証失敗、JSON不正など |
| 回帰テスト | 修正後に既存機能が壊れていないか確認 |
| セキュリティ確認 | 秘密情報がログやGitに含まれないか確認 |

---

## 7. 合格基準

MVPの合格基準は以下とする。

- Gmailの未読メールを取得できる
- Outlookの未読メールを取得できる
- 取得メールを共通形式へ正規化できる
- OpenAIがJSON形式で要約・分類結果を返す
- 予定メールをGoogle Calendarへ登録できる
- LINEへ要約通知が届く
- 処理結果がSupabaseへ保存される
- 同一メールが重複処理されない
- 主要なエラーが `error_logs` に保存される
- APIキーやトークンがGit管理対象に含まれていない

## 9. E2Eテスト

## 9.1 正常系E2E

### 目的

メール取得からLINE通知、Calendar登録、Supabase保存まで一連の流れを確認する。

### 手順

1. Gmailに予定メールを1件用意する
2. Outlookに通常メールを1件用意する
3. n8nのManual Triggerを実行する
4. OpenAIで要約・分類されることを確認する
5. 予定メールがGoogle Calendarへ登録されることを確認する
6. LINEへ要約通知が届くことを確認する
7. Supabaseにログが保存されることを確認する

### 期待結果

- Gmailメールが取得される
- Outlookメールが取得される
- AI分類結果が生成される
- Google Calendarに予定が作成される
- LINE通知が届く
- mail_logs / calendar_logs / notification_logs が保存される
- workflow_runs がsuccessになる

---

## 9.2 異常系E2E

### 目的

一部外部サービスが失敗しても、可能な範囲で処理継続されることを確認する。

### 手順

1. Gmail Credentialを一時的に無効化する
2. Outlookには取得可能なメールを用意する
3. n8nのManual Triggerを実行する
4. Outlook側の処理が継続されることを確認する
5. Gmailエラーがerror_logsに保存されることを確認する
6. LINE通知にエラー概要が含まれることを確認する

### 期待結果

- Gmail取得失敗が記録される
- Outlookメールは処理される
- ワークフロー全体はpartial_successになる
- error_logsにgmail_errorが保存される
