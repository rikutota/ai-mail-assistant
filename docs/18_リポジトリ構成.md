# リポジトリ構成

## 1. 目的

n8n workflow、Supabase migration、テストデータ、検証スクリプトの配置を統一し、GitHub Issueを1タスク・1PRで安全に実装できるようにする。

## 2. 管理対象

```text
ai-mail-assistant/
├── n8n/
│   └── workflows/          # n8nからエクスポートしたworkflow JSON
├── supabase/
│   └── migrations/         # 新規追加方式で管理するSQL migration
├── tests/
│   └── fixtures/           # 匿名化した固定入力と期待結果
└── scripts/                # ローカルとCIで共用する静的検証
```

各ディレクトリの詳細な規則は、配下の `README.md` を参照する。

## 3. 配置ルール

| 対象 | 配置先 | 主な禁止事項 |
| --- | --- | --- |
| n8n workflow | `n8n/workflows/` | credential、接続情報、実行データ、メール本文を含めない |
| Supabase migration | `supabase/migrations/` | 適用済みmigrationを書き換えない |
| テストfixture | `tests/fixtures/` | 個人情報や本番データを使用しない |
| 検証スクリプト | `scripts/` | 既定で外部APIや本番環境へ接続しない |

## 4. 変更単位

- workflow JSON、migration、fixture、検証スクリプトは、対象Issueで明示された場合だけ追加・変更する。
- 異なる領域を同時に変更する必要がなければ、個別Issue・個別PRへ分割する。
- 仕様や運用が変わる場合は、同じPRで関連する `docs/` または `README.md` を更新する。
- APIキー、トークン、パスワード、OAuth情報、個人情報はコミットしない。

## 5. この構成追加時の範囲

初期のディレクトリ追加では配置場所と規則だけを管理する。workflow JSON、SQL migration、fixture、検証スクリプトの実体は、それぞれの実装Issueで追加する。
