# 認証設計書

## 1. 概要

本ドキュメントでは、AIメールアシスタントで使用する外部サービスの認証方式、認証情報の管理方針、必要スコープ、セキュリティ上の注意点を定義する。

本システムはn8nを中心に、以下の外部サービスと連携する。

- Gmail
- Outlook / Microsoft Graph
- OpenAI
- Google Calendar
- LINE Messaging API
- Supabase

MVPでは単一ユーザー利用を前提とし、SaaS化や複数ユーザー認証は対象外とする。

---

## 2. 認証設計の基本方針

## 2.1 基本方針

- APIキーやOAuthトークンはGitHubにコミットしない
- 認証情報はn8n Credentialsで管理する
- `.env.example` にはキー名と、安全な非秘密既定値または空値のみ記載する
- `.env` は `.gitignore` に含める
- 権限は最小権限を原則とする
- 読み取りだけでよいAPIには読み取り権限のみ付与する
- Service Role KeyやSecret Keyは外部公開しない
- トークン漏洩時は即時ローテーションする

---

## 2.2 MVPでの前提

MVPでは、Webアプリケーションやログイン画面は作成しない。

そのため、ユーザー認証ではなく、以下のようなサービス間認証を中心に扱う。

| 認証対象 | 用途 |
|---|---|
| Gmail OAuth2 | Gmailメール取得 |
| Microsoft OAuth2 | Outlookメール取得 |
| Google Calendar OAuth2 | 予定登録 |
| OpenAI API Key | メール解析 |
| LINE Channel Access Token | LINE通知 |
| Supabase API Key / DB接続情報 | ログ保存 |

## 4. Gmail認証設計

## 4.1 用途

Gmailから未読メールを取得するために使用する。

---

## 4.2 認証方式

OAuth2を使用する。

MVPでは、n8nのGmail Credentialを使用して認証する。

---

## 4.3 必要スコープ

MVPではメール取得のみを行うため、以下を使用する。

```text
https://www.googleapis.com/auth/gmail.readonly
```

### スコープ選定理由

- メール一覧取得
- メール詳細取得
- メール本文取得

MVPでは既読化やメール更新を行わないため、書き込み権限は付与しない。

---

## 4.4 将来追加する可能性があるスコープ

処理済みメールを既読化する場合は、以下を検討する。

```text
https://www.googleapis.com/auth/gmail.modify
```

ただし、MVPでは使用しない。

---

## 4.5 取得・管理する認証情報

| 項目 | 用途 | 管理場所 |
|---|---|---|
| GOOGLE_CLIENT_ID | OAuth Client ID | n8n Credentials |
| GOOGLE_CLIENT_SECRET | OAuth Client Secret | n8n Credentials |
| GOOGLE_REFRESH_TOKEN | アクセストークン再発行 | n8n Credentials |

---

## 4.6 セキュリティ方針

- Gmailは読み取り権限のみ付与する
- OAuth Client SecretをGitHubにコミットしない
- Refresh Tokenはn8n Credentialsで管理する
- 既読化を行うまでは `gmail.modify` を付与しない
- 認証エラー時はLINE通知またはerror_logsに記録する

---

## 5. Microsoft Graph / Outlook認証設計

## 5.1 用途

Outlook / Microsoft 365の受信メールを取得するために使用する。

---

## 5.2 認証方式

OAuth2を使用する。

MVPでは、n8nのMicrosoft Outlook Credential、またはHTTP RequestノードのOAuth2 Credentialを使用する。

---

## 5.3 必要権限

MVPではメール取得のみを行うため、以下を使用する。

```text
Mail.Read
```

### 権限選定理由

- Inboxメール一覧取得
- メール本文取得
- 差出人・件名・受信日時の取得

MVPでは既読化やメール更新を行わないため、`Mail.ReadWrite` は使用しない。

---

## 5.4 将来追加する可能性がある権限

処理済みメールを既読化する場合は、以下を検討する。

```text
Mail.ReadWrite
```

ただし、MVPでは使用しない。

## 5.5 Azure / Microsoft Entraで設定する項目

| 項目 | 内容 |
|---|---|
| App registration | Microsoft Graph連携用アプリ |
| Redirect URI | n8nのOAuth2 Callback URL |
| API permissions | Mail.Read |
| Client ID | n8n Credentialsへ設定 |
| Client Secret | n8n Credentialsへ設定 |
| Tenant ID | 必要に応じて設定 |

---

## 5.6 取得・管理する認証情報

| 項目 | 用途 | 管理場所 |
|---|---|---|
| MICROSOFT_CLIENT_ID | OAuth Client ID | n8n Credentials |
| MICROSOFT_CLIENT_SECRET | OAuth Client Secret | n8n Credentials |
| MICROSOFT_TENANT_ID | テナント指定 | n8n Credentials / env |
| MICROSOFT_REFRESH_TOKEN | アクセストークン再発行 | n8n Credentials |

---

## 5.7 セキュリティ方針

- MVPでは `Mail.Read` のみ使用する
- `Mail.ReadWrite` は既読化が必要になるまで付与しない
- Client SecretはGitHubにコミットしない
- Refresh Tokenはn8n Credentialsで管理する
- 個人Microsoftアカウントで検証し、必要に応じて職場・学校アカウントで再検証する

## 6. OpenAI API認証設計

## 6.1 用途

メール本文を解析し、以下を生成するために使用する。

- 要約
- 重要度
- カテゴリ
- 対応要否
- 予定情報

---

## 6.2 認証方式

API Keyを使用する。

---

## 6.3 管理する認証情報

| 項目 | 用途 | 管理場所 |
|---|---|---|
| OPENAI_API_KEY | OpenAI API呼び出し | n8n Credentials / env |

`OPENAI_MODEL` は秘密情報ではない実行設定であり、環境変数で管理する。既定値は `gpt-5.6-luna` とする。API Keyなどの実値はn8n Credentialsを優先し、`.env.example` には記載しない。

---

## 6.4 セキュリティ方針

- API KeyはGitHubにコミットしない
- `.env.example` にはキー名のみ記載する
- n8n Credentialsで管理する
- 漏洩時は即時ローテーションする
- ログにAPI Keyを出力しない
- エラー通知にもAPI Keyを含めない

---

## 6.5 入力データ上の注意

OpenAI APIにはメール本文を送信するため、以下に注意する。

- 不要な本文全文送信を避ける
- 長文メールは必要部分のみ送信する
- 添付ファイルはMVPでは送信しない
- 機密性の高いメールを扱う場合は運用ルールを追加する

## 7.3 必要スコープ

MVPでは予定作成のみを行うため、以下を使用する。

```text
https://www.googleapis.com/auth/calendar.events
```

### スコープ選定理由

- Google Calendarへの予定作成

- 必要最小限のイベント操作

## 7.4 取得・管理する認証情報

| 項目 | 用途 | 管理場所 |
|---|---|---|
| GOOGLE_CLIENT_ID | OAuth Client ID | n8n Credentials |
| GOOGLE_CLIENT_SECRET | OAuth Client Secret | n8n Credentials |

## 7.5 セキュリティ方針

## 9.4 Secret Keyの扱い

`SUPABASE_SECRET_KEY` は強い権限を持つため、以下を徹底する。

- ブラウザに渡さない
- GitHubへコミットしない
- READMEに実値を書かない
- エラーログに出力しない
- n8n Credentialsまたは安全な環境変数で管理する
- 漏洩時は即時ローテーションする

---

## 9.5 RLS方針

Web画面を作らないため、ユーザーごとのRLS制御はMVP対象外とする。

将来的にWebダッシュボードを作る場合は、以下を追加する。

- usersテーブル
- user_idカラム

- ユーザー単位のアクセス制御

## 10.1 用途

---

## 10.2 認証方式

MVPではBasic Authを設定する。

---

## 10.3 管理する認証情報

| 項目 | 用途 | 管理場所 |
|---|---|---|
| N8N_BASIC_AUTH_USER | n8nログインユーザー | env |
| N8N_BASIC_AUTH_PASSWORD | n8nログインパスワード | env |
| N8N_ENCRYPTION_KEY | Credentials暗号化キー | env |

---

## 10.4 セキュリティ方針

- `N8N_BASIC_AUTH_PASSWORD` は強固な値にする
- `N8N_ENCRYPTION_KEY` は固定値として安全に管理する
- n8nを外部公開する場合はHTTPS化する
- 管理画面URLを不用意に公開しない
- Credentialsのスクリーンショットを公開しない

## 11. `.env.example`

`.env.example` には秘密情報の実値を入れず、キー名と安全な非秘密既定値または空値のみ定義する。OAuthトークン、APIキー、パスワードなどは空欄のままにし、実行環境の `.env` またはn8n Credentialsへ登録する。

```env
# OpenAI
OPENAI_API_KEY=
OPENAI_MODEL=gpt-5.6-luna

# LINE
LINE_CHANNEL_ACCESS_TOKEN=
LINE_USER_ID=

# Google OAuth
GOOGLE_CLIENT_ID=
GOOGLE_CLIENT_SECRET=
GOOGLE_REFRESH_TOKEN=

# Microsoft OAuth
MICROSOFT_CLIENT_ID=
MICROSOFT_CLIENT_SECRET=
MICROSOFT_TENANT_ID=
MICROSOFT_REFRESH_TOKEN=

# Supabase API
SUPABASE_URL=
SUPABASE_SECRET_KEY=

# Supabase DB
SUPABASE_DB_HOST=
SUPABASE_DB_PORT=5432
SUPABASE_DB_NAME=postgres
SUPABASE_DB_USER=
SUPABASE_DB_PASSWORD=

# n8n
N8N_BASIC_AUTH_USER=
N8N_BASIC_AUTH_PASSWORD=
N8N_ENCRYPTION_KEY=
TZ=Asia/Tokyo
GENERIC_TIMEZONE=Asia/Tokyo
```

IPv4環境のn8nからPostgreSQLへ接続する場合は、Session pooler（port `5432`）のhostと`postgres.<project-ref>`形式のユーザー名を使用する。接続情報の実値はn8n Credentialsまたはローカル`.env`だけで管理する。

`OPENAI_MODEL`、`TZ`、`GENERIC_TIMEZONE`、DBポート・DB名などの非秘密設定は環境変数で管理する。OAuth Client Secret、Refresh Token、API Key、LINE_USER_ID、Service Role Key、DBパスワードは実値をn8n Credentialsまたは安全な実行環境へ登録し、リポジトリには保存しない。

## 15. トークンローテーション方針

## 15.1 ローテーションが必要なケース

以下の場合は、対象キー・トークンを即時再発行する。

- GitHubへ誤ってコミットした
- ログに出力された
- 画面共有やスクリーンショットで露出した
- 不審なAPI利用がある
- 外部サービスから漏洩警告が出た

---

## 15.2 ローテーション対象

| 対象 | 再発行場所 |
|---|---|
| OpenAI API Key | OpenAI Platform |
| LINE Channel Access Token | LINE Developers Console |
| Google OAuth Client Secret | Google Cloud Console |
| Microsoft Client Secret | Microsoft Entra admin center |
| Supabase Service Role Key | Supabase Dashboard |
| DB Password | Supabase Database Settings |
| n8n Basic Auth Password | env更新 |
| N8N_ENCRYPTION_KEY | 原則変更しない。変更時はCredentials復旧に注意 |

---

## 16. 認証エラー時の対応

| エラー | 想定原因 | 対応 |
|---|---|---|
| Gmail 401 | Access Token期限切れ | Refresh Token確認 |
| Gmail 403 | スコープ不足 | OAuthスコープ確認 |
| Graph 401 | Access Token期限切れ | Microsoft OAuth設定確認 |
| Graph 403 | 権限不足 | API permissions確認 |
| OpenAI 401 | API Key不正 | API Key再設定 |
| Calendar 403 | スコープ不足 | calendar.events権限確認 |
| LINE 401 | Channel Access Token不正 | Token再発行 |
| Supabase 401 | API Key不正 | Key確認 |
| Supabase接続失敗 | DB接続情報不正 | DB Host / Password確認 |
| n8nログイン不可 | Basic Auth不一致 | env確認 |

---

## 17. ログ出力時のマスキング

エラー保存時、以下の値はログに出力しない。

- API Key
- Access Token
- Refresh Token
- Client Secret
- Channel Access Token
- Service Role Key
- DB Password
- Authorization Header
- Cookie
- 個人情報を含む本文全文

---

## 18. n8n Workflow Export時の注意

n8nワークフローをJSONでエクスポートしてGit管理する場合、以下を確認する。

- Credentialsの実値が含まれていないこと
- Authorization Headerが直書きされていないこと
- APIキーがHTTP Requestノードに直接書かれていないこと
- テスト用の個人情報が残っていないこと
- LINE_USER_IDが含まれていないこと

---

## 19. ローカル開発時の注意

ローカル開発では以下を守る。

- `.env` をGit管理しない
- 画面共有時にCredentials画面を開かない
- サンプルメールには実在の個人情報を使わない
- GitHubへpush前に `git diff` を確認する
- 認証情報を含むスクリーンショットをREADMEに載せない

---

## 20. MVPでの認証設定順序

MVPでは以下の順で設定する。

1. OpenAI API Keyを作成
2. LINE Messaging APIのChannel Access Tokenを作成
3. Gmail OAuth2を設定
4. Microsoft OAuth2を設定
5. Google Calendar OAuth2を設定
6. Supabase接続情報を設定
7. n8n Basic Authを設定
8. n8n Credentialsへ登録
9. 接続テストを実行
10. `.env.example` と設計書を更新
