# ユースケース一覧

## 1. 概要

本ドキュメントでは、AIメールアシスタントにおける主要なユースケースを整理する。

本システムは、GmailおよびOutlookからメールを取得し、AIによる要約・分類・予定抽出を行い、LINE通知およびGoogle Calendar登録を自動化する。

---

## 2. アクター

| アクター | 説明 |
|---|---|
| ユーザー | 本システムを利用する個人ユーザー |
| n8n | ワークフローを実行する自動化基盤 |
| Gmail | メール取得元の1つ |
| Outlook | メール取得元の1つ |
| OpenAI | メール要約・分類・予定抽出を行うAI |
| LINE | 要約結果を通知するサービス |
| Google Calendar | 予定を登録するサービス |
| Supabase | 処理ログを保存するDB |

## 4. ユースケース詳細

## UC-001 毎朝メール要約を受け取る

### 概要

ユーザーは毎朝、GmailおよびOutlookに届いたメールの要約をLINEで受け取る。

### アクター

- ユーザー
- n8n
- Gmail
- Outlook
- OpenAI
- LINE
- Supabase

### 事前条件

- n8nのワークフローが有効化されている
- Gmail連携が完了している
- Outlook連携が完了している
- OpenAI APIキーが設定されている
- LINE Messaging APIの設定が完了している

### 基本フロー

1. n8nが毎朝8時にワークフローを開始する
2. Gmailから対象メールを取得する
3. Outlookから対象メールを取得する
4. 取得したメールを共通形式に変換する
5. OpenAIでメール本文を要約する
6. 重要度・カテゴリ・予定情報を判定する
7. LINE通知用のメッセージを作成する
8. LINEへ通知を送信する
9. 処理結果をSupabaseへ保存する

### 代替フロー

- Gmail取得に失敗した場合、Outlook処理は継続する
- Outlook取得に失敗した場合、Gmail処理は継続する
- OpenAI APIに失敗した場合、対象メールを未処理として保存する
- LINE通知に失敗した場合、Supabaseにエラーを保存する

### 事後条件

- ユーザーがLINEでメール要約を確認できる
- 処理結果がSupabaseに保存されている

## UC-002 Gmailの未読メールを取得する

### 概要

Gmailから未読かつ直近24時間以内のメールを取得する。

### アクター

- n8n
- Gmail

### 事前条件

- Gmail APIまたはn8n Gmailノードの認証が完了している

### 基本フロー

1. n8nがGmailへ接続する
2. 未読メールを検索する
3. 直近24時間以内のメールに絞り込む
4. メールID、件名、差出人、本文、受信日時を取得する
5. 後続処理へ渡す

### 事後条件

- Gmailの対象メールが取得されている

---

## UC-003 Outlookの未読メールを取得する

### 概要

Outlookから未読かつ直近24時間以内のメールを取得する。

### アクター

- n8n
- Outlook
- Microsoft Graph API

### 事前条件

- Microsoftアカウント連携が完了している
- Microsoft Graph APIの権限設定が完了している

### 基本フロー

1. n8nがOutlookまたはMicrosoft Graph APIへ接続する
2. 受信トレイ内の未読メールを検索する
3. 直近24時間以内のメールに絞り込む
4. メールID、件名、差出人、本文、受信日時を取得する
5. 後続処理へ渡す

### 事後条件

- Outlookの対象メールが取得されている

---

## UC-004 メール内容をAIで要約する

### 概要

取得したメール本文をOpenAI APIへ渡し、短い要約を生成する。

### アクター

- n8n
- OpenAI

### 事前条件

- OpenAI APIキーが設定されている
- 対象メールの本文が取得できている

### 基本フロー

1. n8nがメール本文を整形する
2. 件名、差出人、本文をOpenAI APIへ送信する
3. OpenAIが要約を生成する
4. 要約結果を後続処理へ渡す

### 事後条件

- メールごとに要約文が生成されている

---

## UC-005 メールの重要度を判定する

### 概要

AIがメール内容をもとに重要度を High / Medium / Low に分類する。

### アクター

- n8n
- OpenAI

### 判定基準

| 重要度 | 基準 |
|---|---|
| High | 返信・対応・期限・予定登録が必要 |
| Medium | 内容確認が必要 |
| Low | 広告、通知、重要度の低いメール |

### 事後条件

- メールごとに重要度が設定されている

---

## UC-006 予定メールを検出する

### 概要

AIがメール本文から予定情報を抽出する。

### アクター

- n8n
- OpenAI

### 抽出項目

- 予定タイトル
- 開始日時
- 終了日時
- 場所
- 説明

### 基本フロー

1. メール本文をOpenAI APIへ渡す
2. AIが予定情報の有無を判定する
3. 予定情報がある場合、JSON形式で返却する
4. Google Calendar登録処理へ渡す

### 事後条件

- 予定メールかどうかが判定されている
- 予定メールの場合、カレンダー登録に必要な情報が抽出されている

---

## UC-007 Google Calendarへ予定登録する

### 概要

予定情報が抽出できたメールをGoogle Calendarへ登録する。

### アクター

- n8n
- Google Calendar

### 登録条件

- 予定タイトルが存在する
- 開始日時が存在する
- 同一メールIDで未登録である

### 基本フロー

1. 予定情報を受け取る
2. 同一メールIDで登録済みか確認する
3. 未登録の場合、Google Calendarへ予定を作成する
4. 作成結果をSupabaseへ保存する

### 事後条件

- Google Calendarに予定が登録されている
- 登録結果がSupabaseに保存されている

---

## UC-010 同じメールの重複処理を防ぐ

### 概要

同じメールを複数回処理しないようにする。

### アクター

- n8n
- Supabase

### 基本フロー

1. メールIDとメールサービス種別を取得する
2. Supabaseで処理済みか確認する
3. 未処理の場合のみAI処理を実行する
4. 処理後、メールIDを保存する

### 事後条件

- 同一メールが複数回通知・登録されない

---

## UC-011 エラーを記録する

### 概要

APIエラーや処理失敗をSupabaseへ保存する。

### アクター

- n8n
- Supabase

### 対象エラー

- Gmail取得失敗
- Outlook取得失敗
- OpenAI API失敗
- Google Calendar登録失敗
- LINE通知失敗
- Supabase保存失敗

### 事後条件

- エラー内容を後から確認できる

---

## UC-012 エラーをLINEで通知する

### 概要

重大なエラーが発生した場合、ユーザーへLINEで通知する。

### アクター

- n8n
- LINE
- ユーザー

### 通知対象

- GmailとOutlookの両方が取得失敗
- LINE通知以外の主要処理が停止
- Google Calendar登録が連続して失敗

### 事後条件

- ユーザーが障害に気づける

---

## UC-013 処理履歴を確認する

### アクター

- ユーザー
- Supabase

### 確認項目

- 処理日時
- メール件名
- 差出人
- 要約
- 重要度
- カテゴリ
- カレンダー登録有無
- エラー内容

### 事後条件

- ユーザーが過去の処理結果を確認できる
