# メール分類仕様書

## 1. 概要

本ドキュメントでは、AIメールアシスタントにおけるメール分類ルールを定義する。

本システムでは、GmailおよびOutlookから取得したメールをAIで解析し、以下の観点で分類する。

- 重要度
- カテゴリ
- 対応要否
- 予定メール判定
- LINE通知上の表示グループ
- Google Calendar登録対象かどうか

---

## 2. 分類の目的

メール分類の目的は、ユーザーが毎朝短時間で重要なメールを把握できるようにすることである。

### 実現したいこと

- 重要メールを見落とさない
- 広告や低重要度メールを通知本文で目立たせない
- 予定メールをGoogle Calendarへ登録できる形にする
- 対応が必要なメールを明確にする
- LINE通知を読みやすく整理する

---

## 3. 分類項目

| 項目 | 値 | 説明 |
|---|---|---|
| priority | High / Medium / Low | メールの重要度 |
| category | schedule / task / notice / invoice / promotion / other | メールカテゴリ |
| requiresAction | true / false | ユーザー対応が必要か |
| isSchedule | true / false | Google Calendar登録候補か |
| confidence | 0.0〜1.0 | AI判定の信頼度 |

---

## 4. priority分類仕様

## 4.1 priority一覧

| priority | 意味 | LINE表示 |
|---|---|---|
| High | 重要・緊急・対応が必要 | 重要メール欄に表示 |
| Medium | 確認した方がよい | 通常メール欄に表示 |
| Low | 広告・通知・重要度が低い | 原則件数のみ表示 |

---

## 4.2 Highの条件

以下のいずれかに該当する場合、`priority=High` とする。

- 返信が必要
- 提出が必要
- 明確な期限がある
- 面接、会議、打ち合わせなどの予定がある
- 支払い、請求、契約に関する内容
- 障害、トラブル、緊急連絡
- 就職活動や業務に関する重要連絡
- ユーザーが行動しないと不利益が発生する可能性がある

### Highの例

| メール内容 | 理由 |
|---|---|
| 面接日程の案内 | 予定かつ重要 |
| 資料提出依頼 | 対応期限がある |
| 請求書の支払い依頼 | 支払い対応が必要 |
| 障害発生通知 | 緊急性が高い |
| 内定・選考結果連絡 | 就職活動上重要 |

---

## 4.3 Mediumの条件

以下に該当する場合、`priority=Medium` とする。

- 内容確認は必要だが、即時対応は不要
- 重要な案内だが、返信や作業は不要
- 参考情報として確認すべき
- 日程調整中だが確定日時はない
- サービス利用に関する通常通知

### Mediumの例

| メール内容 | 理由 |
|---|---|
| 大学からの説明会案内 | 確認した方がよい |
| サービス仕様変更のお知らせ | 重要だが即時対応不要 |
| 打ち合わせ候補日の連絡 | 日時未確定 |
| イベント開催案内 | 興味があれば確認 |

---

## 4.4 Lowの条件

以下に該当する場合、`priority=Low` とする。

- 広告
- キャンペーン
- セール案内
- ニュースレター
- 自動配信メール
- SNSやサービスの軽微な通知
- 対応不要な宣伝メール

### Lowの例

| メール内容 | 理由 |
|---|---|
| セールのお知らせ | 広告 |
| メルマガ | 対応不要 |
| クーポン配信 | 販促 |
| ログイン通知 | 原則確認のみ |
| おすすめ記事通知 | 低重要度 |

---

## 5. category分類仕様

## 5.1 category一覧

| category | 説明 |
|---|---|
| schedule | 予定・会議・面接・イベント |
| task | 作業依頼・返信依頼・提出依頼 |
| notice | 通知・案内・お知らせ |
| invoice | 請求・支払い・領収書 |
| promotion | 広告・キャンペーン・メルマガ |
| other | その他 |

---

## 5.2 schedule

### 定義

会議、面接、打ち合わせ、訪問、イベント、説明会など、日時が関係する予定メール。

### scheduleにする条件

- 会議、面接、打ち合わせなどの予定が含まれる
- イベントや説明会の日時が含まれる
- ユーザーが参加する可能性がある
- 日程調整に関する内容である

### 例

| 件名・内容 | category |
|---|---|
| 一次面接の日程について | schedule |
| 7/15 打ち合わせのご案内 | schedule |
| 説明会開催のお知らせ | schedule |
| 現場点検の日程確認 | schedule |

### 注意

`category=schedule` であっても、必ず `isSchedule=true` になるわけではない。

日時が曖昧な場合は、以下のように分類する。

```json
{
  "category": "schedule",
  "isSchedule": false
}
```

---

## 5.3 task

### 定義

ユーザーに何らかの作業、返信、提出、確認を求めるメール。

### taskにする条件

- 資料提出が必要
- 返信が必要
- 確認依頼がある
- 修正依頼がある
- 期限付きの作業がある

### 例

| 件名・内容 | category |
|---|---|
| 資料提出のお願い | task |
| 内容確認をお願いします | task |
| 修正依頼 | task |
| 7/20までに回答してください | task |

---

## 5.4 notice

### 定義

サービス、大学、企業、システムなどからの案内や通知。

### noticeにする条件

- サービス変更通知
- メンテナンス通知
- 大学や企業からのお知らせ
- システム通知
- 参考情報としての案内

### 例

| 件名・内容 | category |
|---|---|
| サービスメンテナンスのお知らせ | notice |
| 大学からの連絡 | notice |
| 利用規約変更のお知らせ | notice |
| ログイン通知 | notice |

---

## 5.5 invoice

### 定義

請求、支払い、領収書、料金、決済に関するメール。

### invoiceにする条件

- 請求書
- 領収書
- 支払い依頼
- 決済完了
- 利用料金通知
- サブスクリプション更新

### 例

| 件名・内容 | category |
|---|---|
| 請求書を送付します | invoice |
| お支払いのお願い | invoice |
| 領収書発行のお知らせ | invoice |
| 月額料金のお知らせ | invoice |

---

## 5.6 promotion

### 定義

広告、販促、キャンペーン、セール、メルマガ。

### promotionにする条件

- セール案内
- キャンペーン
- クーポン
- おすすめ商品
- メールマガジン
- 広告目的の案内

### 例

| 件名・内容 | category |
|---|---|
| 週末限定セール | promotion |
| クーポン配布中 | promotion |
| おすすめ商品のお知らせ | promotion |
| メルマガ配信 | promotion |

---

## 5.7 other

### 定義

上記カテゴリに明確に分類できないメール。

### otherにする条件

- 内容が短すぎる
- 本文が取得できない
- 文脈が不明
- 複数カテゴリにまたがり、主要カテゴリを特定できない
- AIの信頼度が低い

---

## 6. requiresAction判定仕様

## 6.1 定義

`requiresAction` は、ユーザーが何らかの対応を行う必要がある場合に `true` とする。

---

## 6.2 trueにする条件

| 条件 | 例 |
|---|---|
| 返信が必要 | ご返信ください |
| 提出が必要 | 資料を提出してください |
| 確認が必要 | 内容をご確認ください |
| 支払いが必要 | 期日までにお支払いください |
| 参加が必要 | 面接に参加してください |
| 判断が必要 | 希望日を選択してください |
| 期限がある | 7/20までに対応してください |

---

## 6.3 falseにする条件

| 条件 | 例 |
|---|---|
| 単なる通知 | メンテナンスのお知らせ |
| 広告 | セール情報 |
| 自動配信 | ログイン通知 |
| 完了報告 | 決済完了のお知らせ |
| 参考情報 | ニュースレター |

---

## 7. isSchedule判定仕様

## 7.1 定義

`isSchedule` は、Google Calendarへ登録すべき予定である場合に `true` とする。

---

## 7.2 trueにする条件

以下をすべて満たす場合、`isSchedule=true` とする。

- 日付または日時が明確
- 予定タイトルを生成できる
- ユーザーが参加または対応する予定である
- 会議、面接、打ち合わせ、訪問、イベントなどの予定である
- 過去の日時ではない
- 仮日程ではない

---

## 7.3 falseにする条件

以下の場合は `isSchedule=false` とする。

- 日時が曖昧
- 候補日だけで確定していない
- 締切日であり、予定ではない
- 広告イベントの案内のみ
- 過去の予定
- 本文に日時がない
- 日程調整中
- ユーザーが参加する予定か不明

---

## 7.4 判定例

| 内容 | category | isSchedule | 理由 |
|---|---|---:|---|
| 7/15 10:00から面接 | schedule | true | 日時と予定が明確 |
| 来週あたり打ち合わせ | schedule | false | 日時が曖昧 |
| 7/20までに資料提出 | task | false | 締切であり予定ではない |
| セミナー開催のお知らせ | schedule | false | 参加予定とは限らない |
| 参加登録済みセミナーの案内 | schedule | true | ユーザーの参加予定と判断できる |

---

## 8. confidence判定仕様

## 8.1 定義

`confidence` はAI判定の信頼度を `0.0` から `1.0` で表す。

| 値 | 意味 |
|---|---|
| 0.9〜1.0 | 明確に判断できる |
| 0.7〜0.89 | おおむね判断できる |
| 0.5〜0.69 | やや曖昧 |
| 0.0〜0.49 | 判断困難 |

---

## 8.2 運用ルール

| 条件 | 処理 |
|---|---|
| confidence >= 0.7 | 通常処理 |
| confidence < 0.7 かつ isSchedule=true | カレンダー登録しない |
| confidence < 0.5 | categoryをother寄りに扱う |
| confidence < 0.7 | LINE通知に要確認として表示 |

---

## 9. LINE通知グルーピング仕様

## 9.1 表示グループ

LINE通知では、メールを以下のグループに分けて表示する。

| 表示グループ | 条件 |
|---|---|
| 重要 | priority = High |
| 通常 | priority = Medium |
| 低重要度 | priority = Low |
| 予定登録 | isSchedule = true かつ登録成功 |
| 要確認 | confidence < 0.7 |
| エラー | 処理失敗 |

---

## 9.2 表示順

LINE通知では、以下の順で表示する。

1. 重要メール
2. 要対応メール
3. 通常メール
4. 予定登録結果
5. 低重要度メール件数
6. エラー概要
7. 処理件数

---

## 9.3 表示ルール

### High

本文に要約を表示する。

```text
【重要】
1. A社：打ち合わせ日程について
   7/15 10:00からA社との打ち合わせがあります。
```

### Medium

件名と要約を表示する。

```text
【通常】
1. 大学：イベント案内
   来週の説明会に関する案内です。
```

### Low

原則として件数のみ表示する。

```text
【低重要度】
広告・通知メール：5件
```

### 要確認

AI判定の信頼度が低い場合に表示する。

```text
【要確認】
1. B社：打ち合わせ候補について
   日時が曖昧なため、カレンダー登録していません。
```

---

## 10. Google Calendar登録分類仕様

## 10.1 登録条件

Google Calendarへ登録する条件は以下とする。

```text
isSchedule = true
confidence >= 0.7
event.title が存在する
event.startDateTime が存在する
event.endDateTime が存在する
source + messageId が未登録
```

---

## 10.2 登録しない条件

以下の場合は登録しない。

- `isSchedule=false`
- `confidence < 0.7`
- 開始日時がない
- タイトルがない
- 既に登録済み
- 候補日だけで確定していない
- 広告イベント
- 締切日だけのタスク

---

## 10.3 登録対象例

| メール内容 | 登録 |
|---|---:|
| 7/15 10:00 一次面接 | する |
| 8/1 13:00 打ち合わせ | する |
| 来週どこかで相談 | しない |
| 7/20までに提出 | しない |
| セミナー開催のお知らせ | 原則しない |
| 申し込み済みセミナーの参加案内 | する |

---

## 11. 複数分類に該当する場合

## 11.1 基本方針

1通のメールが複数カテゴリに該当する場合、主目的を優先して1つの `category` に分類する。

---

## 11.2 優先順位

カテゴリが競合する場合は、以下の優先順位で分類する。

```text
schedule
invoice
task
notice
promotion
other
```

### 例

| 内容 | category | 理由 |
|---|---|---|
| 面接日程と返信依頼 | schedule | 予定が主目的 |
| 請求書送付と支払い期限 | invoice | 支払いが主目的 |
| 資料提出依頼と説明会案内 | task | 提出依頼が主目的 |
| キャンペーン兼イベント案内 | promotion | 広告目的が主目的 |

---

## 12. 分類結果のJSON形式

AIは以下の形式で分類結果を返す。

```json
{
  "summary": "7/15 10:00からA社との打ち合わせがあります。",
  "priority": "High",
  "category": "schedule",
  "requiresAction": true,
  "isSchedule": true,
  "event": {
    "title": "A社打ち合わせ",
    "startDateTime": "2026-07-15T10:00:00+09:00",
    "endDateTime": "2026-07-15T11:00:00+09:00",
    "location": "オンライン",
    "description": "A社との打ち合わせ。元メール件名: 打ち合わせ日程について"
  },
  "confidence": 0.95,
  "reason": "日時と打ち合わせ内容が明確に記載されているため"
}
```

## 13. 分類補正ルール

AI出力後、n8n側で以下の補正を行う。

| 状態 | 補正 |
|---|---|
| priorityが不正 | Medium |
| categoryが不正 | other |
| confidenceが範囲外 | 0.5 |
| isSchedule=true かつ event=null | isSchedule=false |
| startDateTimeなし | isSchedule=false |
| Low かつ requiresAction=true | priorityをMedium以上に補正 |
| invoice かつ支払い期限あり | priorityをHighに補正 |
| schedule かつ日時明確 | isSchedule候補として扱う |

## 15. MVPでの分類方針

MVPでは、以下を優先する。

- 重要メールをLowにしない
- 広告メールをHighにしない
- 予定メールを誤って登録しない
- 曖昧な予定はカレンダー登録しない
- LINE通知が長くなりすぎないようにする
- Lowメールは件数中心で扱う

---

## 16. 今後の改善候補

MVP後は以下を検討する。

- ユーザーごとの重要度カスタマイズ
- 特定送信者を常にHigh扱いにする
- 特定ドメインをLow扱いにする
- TODO抽出の追加
- 締切日をタスク管理ツールへ登録
- LINE通知のFlex Message化
- 分類結果の手動修正機能
- 分類精度の評価ログ保存
