# デプロイ手順書

## 1. 概要

本ドキュメントでは、AIメールアシスタントのMVPを実行環境へデプロイする手順を定義する。

本システムは、n8nを中心に以下の外部サービスを連携する。

- Gmail
- Outlook / Microsoft Graph
- OpenAI API
- LINE Messaging API
- Google Calendar API
- Supabase

MVPでは、Webアプリケーションは作成せず、n8nワークフローを実行基盤として利用する。

---

## 2. デプロイ対象

MVPでデプロイする対象は以下とする。

| 対象 | 内容 |
|---|---|
| n8n | ワークフロー実行基盤 |
| Supabase | PostgreSQL DB |
| n8n Workflow | メール取得・AI要約・通知・保存処理 |
| 環境変数 | APIキー・接続情報 |
| Credentials | OAuth認証情報・APIキー |
| GitHub Repository | 設計書・設定ファイル・ワークフロー定義管理 |

---

## 3. MVPの推奨構成

## 7. `.env.example` の準備

`.env.example` には秘密情報の実値を入れず、キー名と安全な非秘密既定値または空値のみ記載する。

```env
# OpenAI
OPENAI_API_KEY=
OPENAI_MODEL=gpt-5.6-luna

# LINE
LINE_CHANNEL_ACCESS_TOKEN=
LINE_USER_ID=

# Google OAuth
GOOGLE_CLIENT_ID=
GOOGLE_CLIENT_SECRET=
GOOGLE_REFRESH_TOKEN=

# Microsoft OAuth
MICROSOFT_CLIENT_ID=
MICROSOFT_CLIENT_SECRET=
MICROSOFT_TENANT_ID=
MICROSOFT_REFRESH_TOKEN=

# Supabase API
SUPABASE_URL=
SUPABASE_SECRET_KEY=

# Supabase DB
SUPABASE_DB_HOST=
SUPABASE_DB_PORT=5432
SUPABASE_DB_NAME=postgres
SUPABASE_DB_USER=
SUPABASE_DB_PASSWORD=

# n8n
N8N_BASIC_AUTH_USER=
N8N_BASIC_AUTH_PASSWORD=
N8N_ENCRYPTION_KEY=
TZ=Asia/Tokyo
GENERIC_TIMEZONE=Asia/Tokyo
```

IPv4環境から常駐するn8nを接続する場合、Supabase DashboardのConnect画面にあるSession poolerを使用する。`SUPABASE_DB_PORT`は`5432`、`SUPABASE_DB_USER`にはpooler用の`postgres.<project-ref>`形式を設定する。host、user、passwordの実値は`.env.example`やGitHubへ記載しない。

`OPENAI_MODEL`、`TZ`、`GENERIC_TIMEZONE`、DBポート・DB名は非秘密設定として環境変数で管理する。OAuth情報、APIキー、LINE_USER_ID、Service Role Key、DBパスワードなどの実値はn8n Credentialsまたはデプロイ先の安全な環境変数へ登録し、`.env.example` やworkflow JSONには記載しない。

## 10. n8nローカル起動手順

## 10.1 Docker Compose作成

実装開始時に、ルート直下へ `docker-compose.yml` を作成する。

```yaml
services:
  n8n:
    image: n8nio/n8n:latest
    ports:
      - "5678:5678"
    environment:
      - TZ=Asia/Tokyo
      - GENERIC_TIMEZONE=Asia/Tokyo
      - N8N_ENCRYPTION_KEY=${N8N_ENCRYPTION_KEY}
    volumes:
      - ./data/n8n:/home/node/.n8n
    restart: unless-stopped
```

---

## 10.2 `.env` 作成

ローカル環境では `.env.example` をコピーして `.env` を作成する。

```bash
cp .env.example .env
```

Windows PowerShellの場合：

```powershell
Copy-Item .env.example .env
```

`.env` には実際の値を設定する。

注意：

```text
.env はGitHubへコミットしない
```

---

## 10.3 n8n起動

```bash
docker compose up -d
```

ログ確認：

```bash
docker compose logs -f n8n
```

停止：

```bash
docker compose down
```

---

## 10.4 n8nアクセス

ブラウザで以下へアクセスする。

```text
http://localhost:5678
```

初回起動後、n8nの管理ユーザーを作成する。

## 12. Gmail接続設定

## 12.1 Google Cloud設定

1. Google Cloud Consoleでプロジェクトを作成する
2. Gmail APIを有効化する
3. OAuth Consent Screenを設定する
4. OAuth Client IDを作成する
5. Redirect URIにn8nのOAuth Callback URLを設定する
6. Client ID / Client Secretをn8n Credentialsへ登録する

---

## 12.2 Gmail接続テスト

n8nでGmailノードを作成し、以下の条件で取得テストする。

```text
in:inbox is:unread newer_than:1d
```

確認項目：

- メールIDが取得できる
- 件名が取得できる
- 差出人が取得できる
- 本文が取得できる

---

## 13. Outlook / Microsoft Graph接続設定

## 13.1 Microsoft側設定

1. Microsoft Entra admin centerでApp registrationを作成する

## 20. ロールバック手順

## 20.1 ワークフロー修正失敗時

1. n8nで対象ワークフローを無効化する
2. GitHub上の前回正常版workflow JSONを確認する
3. n8nへ前回版をImportする
4. Manual Triggerで動作確認する
5. 問題なければSchedule Triggerを再有効化する

---

## 20.2 DB変更失敗時

MVPではDB migrationツールを導入しないため、DDL変更前に以下を行う。

- 変更SQLをGit管理する
- 既存テーブル構造を確認する
- 必要に応じてSupabaseのバックアップ機能を利用する
- 破壊的変更は避ける

---

## 20.3 Credentials不備時

1. 対象Credentialを再作成する
2. ワークフロー内の参照Credentialを差し替える
3. 単体テストを実行する
4. E2Eテストを実行する

---

## 21. 運用開始手順

MVP運用開始前に以下を実施する。

## 22. デプロイ時の注意点

## 22.1 セキュリティ

- `.env` をGitHubへpushしない
- Credentials画面のスクリーンショットを公開しない
- APIキーをREADMEに書かない
- workflow JSONに秘密情報が含まれていないか確認する
- Supabase Service Role Keyを外部公開しない

---

## 22.2 コスト

以下のサービスは利用量に応じて料金が発生する可能性がある。

- OpenAI API
- n8n Cloud
- VPS
- Supabase
- Microsoft / Googleの一部設定

MVPでは少量実行に抑え、メール取得件数やOpenAI入力文字数を制限する。

---

## 22.3 個人情報

メール本文には個人情報が含まれる可能性がある。

MVPでは以下の方針とする。

- メール本文全文はDB保存しない
- body_previewのみ保存する
- ログに本文全文を出さない
- GitHubに実メール内容を載せない

---
