# AIプロンプト設計書

## 1. 概要

本ドキュメントでは、AIメールアシスタントで使用するOpenAI API向けプロンプト設計を定義する。

本システムでは、GmailおよびOutlookから取得したメール本文をAIに渡し、以下の情報をJSON形式で取得する。

- メール要約
- 重要度判定
- カテゴリ分類
- 対応要否
- 予定メール判定
- Google Calendar登録用イベント情報

---

## 2. AI処理の目的

AI処理の目的は、メール本文を人間が読む前に、短時間で重要情報を把握できる形へ変換することである。

### 主な役割

| 項目 | 内容 |
|---|---|
| 要約 | メール本文を短く要約する |
| 重要度判定 | High / Medium / Low に分類する |
| カテゴリ分類 | schedule / task / notice / invoice / promotion / other に分類する |
| 対応要否判定 | ユーザーの対応が必要か判定する |
| 予定抽出 | 日時・場所・タイトルを抽出する |
| JSON生成 | n8nで処理しやすい形式に整形する |

---

## 3. 入力データ

OpenAI APIには、正規化済みメールオブジェクトを渡す。

```json
{
  "source": "gmail",
  "messageId": "string",
  "senderName": "A社 担当者",
  "senderEmail": "sender@example.com",
  "subject": "打ち合わせ日程について",
  "body": "メール本文",
  "receivedAt": "2026-07-12T08:00:00+09:00"
}
```

---

## 4. 出力データ

AIは必ず以下のJSON形式のみを返す。

```json
{
  "summary": "メール内容の要約",
  "priority": "High",
  "category": "schedule",
  "requiresAction": true,
  "isSchedule": true,
  "event": {
    "title": "A社打ち合わせ",
    "startDateTime": "2026-07-15T10:00:00+09:00",
    "endDateTime": "2026-07-15T11:00:00+09:00",
    "location": "オンライン",
    "description": "A社との打ち合わせ。元メール件名: 打ち合わせ日程について"
  },
  "confidence": 0.92,
  "reason": "日時と打ち合わせ内容が明確に記載されているため"
}
```

---

## 5. 出力フィールド定義

| フィールド | 型 | 必須 | 説明 |
|---|---|---|---|
| summary | string | YES | メール要約 |
| priority | string | YES | High / Medium / Low |
| category | string | YES | メールカテゴリ |
| requiresAction | boolean | YES | ユーザー対応が必要か |
| isSchedule | boolean | YES | カレンダー登録候補か |
| event | object / null | YES | 予定情報 |
| confidence | number | YES | 判定信頼度。0〜1 |
| reason | string | YES | 判定理由 |

---

## 6. priority定義

| priority | 基準 |
|---|---|
| High | 期限、返信、作業、予定、支払い、面接、重要な連絡が含まれる |
| Medium | 確認した方がよいが、即時対応は不要 |
| Low | 広告、メルマガ、自動通知、重要度の低い案内 |

### Highにする例

- 返信依頼がある
- 提出期限がある
- 面接・打ち合わせ・会議がある
- 支払い・請求に関する内容
- トラブル・障害・緊急連絡
- 就活や仕事に関わる重要連絡

### Lowにする例

- セール案内
- ニュースレター
- 自動配信通知
- 広告
- キャンペーン情報

---

## 7. category定義

| category | 説明 |
|---|---|
| schedule | 会議、面接、打ち合わせ、イベントなど予定に関するメール |
| task | 提出、確認、返信、作業依頼などタスクに関するメール |
| notice | サービス通知、大学・企業からの案内 |
| invoice | 請求、支払い、領収書、料金に関するメール |
| promotion | 広告、キャンペーン、メルマガ |
| other | 上記に当てはまらないもの |

---

## 8. requiresAction判定

`requiresAction` は、ユーザーが何らかの対応をする必要がある場合に `true` とする。

### trueにする条件

- 返信が必要
- 提出が必要
- 確認後に判断が必要
- 支払いが必要
- 予定参加が必要
- カレンダー登録が必要
- 期限がある

### falseにする条件

- 単なる通知
- 広告
- 自動配信
- 既に完了した内容の報告
- 参考情報のみ

---

## 9. isSchedule判定

`isSchedule` は、Google Calendar登録候補である場合に `true` とする。

### trueにする条件

以下をすべて満たす場合。

- 日付または日時が明確
- 予定タイトルを作成できる
- 会議、面接、打ち合わせ、イベント、訪問などの予定である
- ユーザーが参加・対応する可能性が高い

### falseにする条件

- 日時が不明確
- 単なる締切日であり、予定として登録すべきでない
- 広告イベントの案内のみ
- 過去の予定
- 仮の日程で確定していない

---

## 10. event定義

`isSchedule=true` の場合、`event` を生成する。

```json
{
  "title": "A社打ち合わせ",
  "startDateTime": "2026-07-15T10:00:00+09:00",
  "endDateTime": "2026-07-15T11:00:00+09:00",
  "location": "オンライン",
  "description": "A社との打ち合わせ。元メール件名: 打ち合わせ日程について"
}
```

`isSchedule=false` の場合は、`event` は `null` とする。

```json
{
  "event": null
}
```

---

## 11. 日時抽出ルール

### 11.1 基本ルール

- 日時はISO 8601形式で返す
- タイムゾーンは `+09:00` を基本とする
- 年が本文にない場合は、受信日時をもとに最も自然な年を補完する
- 終了日時がない場合は、開始日時の1時間後を設定する
- 日時が曖昧な場合は `isSchedule=false` とする

### 11.2 年の補完

本文に「7月15日 10:00」とだけある場合、`receivedAt` の年を使って補完する。

例：

```json
{
  "receivedAt": "2026-07-12T08:00:00+09:00",
  "body": "7月15日 10:00に打ち合わせをお願いします。"
}
```

出力：

```json
{
  "startDateTime": "2026-07-15T10:00:00+09:00",
  "endDateTime": "2026-07-15T11:00:00+09:00"
}
```

### 11.3 終了日時の補完

本文に開始時刻のみある場合、終了日時は開始時刻の1時間後とする。

### 11.4 曖昧な日時

以下の場合は予定登録しない。

- 「来週あたり」
- 「近日中」
- 「都合のよい日」
- 「候補日を後ほど送ります」
- 「日程調整中」

## 12. title生成ルール

予定タイトルは、短く分かりやすく作成する。

### 形式

```text
{相手先} {内容}
```

### 例

| メール内容 | title |
|---|---|
| A社との打ち合わせ | A社打ち合わせ |
| 一次面接の案内 | 一次面接 |
| 大学説明会 | 大学説明会 |
| 現場点検依頼 | 現場点検 |

---

## 13. summary生成ルール

summaryは、LINE通知に表示する前提で短く作成する。

### 条件

- 1〜2文
- 100文字以内を目安
- 重要な日付・期限・対応内容を含める
- 不要な挨拶文は省略する
- 推測しすぎない

### 良い例

```text
7/15 10:00からA社との打ち合わせがあります。オンライン参加URLは本文に記載されています。
```

### 悪い例

```text
いつもお世話になっております、という挨拶から始まり、A社の担当者から日程について連絡がありました。
```

---

## 14. confidence定義

AI判定の信頼度を `0.0` から `1.0` で返す。

| 値 | 意味 |
|---|---|
| 0.9〜1.0 | 明確に判断できる |
| 0.7〜0.89 | ほぼ判断できる |
| 0.5〜0.69 | やや曖昧 |
| 0.0〜0.49 | 判断困難 |

### 運用方針

- `confidence < 0.7` かつ `isSchedule=true` の場合、カレンダー登録はしない
- `confidence < 0.5` の場合、categoryは `other` に寄せる
- 低信頼度の場合、LINE通知に「要確認」と表示する

---

## 15. システムプロンプト

```text
あなたはメール内容を要約・分類するAIアシスタントです。
入力されたメールを読み、指定されたJSON形式のみで出力してください。

目的:
- メール内容を短く要約する
- 重要度を判定する
- カテゴリを分類する
- ユーザー対応が必要か判定する
- 予定情報がある場合はGoogle Calendar登録用データを抽出する

出力ルール:
- 必ずJSONのみを出力する
- Markdownを出力しない
- 説明文をJSONの外に出力しない
- 存在しない情報を推測しすぎない
- 日時が曖昧な場合は isSchedule=false とする
- eventが不要な場合は null とする
- priorityは High, Medium, Low のいずれかにする
- categoryは schedule, task, notice, invoice, promotion, other のいずれかにする
- confidenceは0.0〜1.0の数値にする
```

## 19. n8nでの検証ルール

AI出力後、n8nのCodeノードで以下を検証する。

### 検証項目

| 項目 | 対応 |
|---|---|
| JSONとしてパースできない | error_logsへ保存 |
| summaryが空 | 件名をもとに補完、またはfailed扱い |
| priorityが不正 | Mediumに補正 |
| categoryが不正 | otherに補正 |
| confidenceが範囲外 | 0.5に補正 |
| isSchedule=true だがeventがnull | isSchedule=falseに補正 |
| startDateTimeがない | isSchedule=falseに補正 |
| endDateTimeがない | startDateTimeの1時間後に補完 |

---

## 20. カレンダー登録判定

Google Calendarへ登録する条件は以下とする。

```text
isSchedule = true
confidence >= 0.7
event.title is not empty
event.startDateTime is not empty
event.endDateTime is not empty
```

条件を満たさない場合、カレンダー登録は行わない。

| isSchedule | 予定登録候補 |

## 22. プロンプト改善方針

プロンプトは以下の観点で継続的に改善する。

- JSON形式が崩れないか
- 重要メールをLowに分類していないか
- 広告メールをHighに分類していないか
- 曖昧な予定を誤ってカレンダー登録していないか
- 要約が長すぎないか
- 日時補完が自然か
- 日本語メールに強いか
- 英語メールにも対応できるか
